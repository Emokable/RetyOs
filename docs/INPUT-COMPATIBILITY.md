# 输入设备与蓝牙翻页器排查

当前容器仅向 Android 暴露经名称确认的 `pt_mt` 触摸屏；蓝牙配对仍由
Kindle 原系统负责。蓝牙显示已连接不代表 Android 能收到翻页键。
尚未实现蓝牙翻页器的设备映射、热插拔及 Android 按键兼容验证。

`device/kindle-android/diagnose-input.sh` 是只读诊断脚本，可分别在原系统、
Android 活跃、冻结返回和完整退出后运行并保存输出。它不会读取进程命令行，
也不会修改蓝牙配对、独占输入设备或重启服务。设备描述可能包含蓝牙地址，
公开诊断结果前请删除个人设备标识。

2026-10-29 本地修复候选：

- 触摸屏与电源键按设备身份发现，不再假设宿主的 event1/event0 固定不变。
  多个候选设备或身份不符时拒绝接管。
- Android 独占输入模式不再修改共享的内核按键重复参数。此项是外设兼容性
  防护；默认仅映射触摸屏时，不足以解释蓝牙翻页器故障。
- 输入已释放时，新打开的触摸设备不会再次独占，避免冻结交接期间抢回触控。

以上不是蓝牙翻页器已经修好的声明。还需要实机对比四种状态的设备、原生进程
状态与按键事件。退出后失效的根因尚未确认；不得以盲目重启蓝牙服务或重置配对
掩盖问题。验收须包括容器内翻页、冻结返回、完整退出、断开重连，以及原生翻页
功能恢复。本轮已连接实机并部署输入交接候选，但实体翻页器未连接，尚未进行按键验收。


## 本轮实机与构建记录

- 原系统配置确认翻页器经 `input_manager` 转换为 `kindle-input-pt` 虚拟键盘，
  并有设备白名单。当前 Android 仍未映射此虚拟键盘，不能宣称支持翻页器。
- 输入防护候选 `32417a1c73d24a68350875ba0670c984792f1d8633358b4bfc855d9208ba4924`
  已部署。两轮冻结返回软件就绪为 3082/2248 ms，恢复为 1404/1328 ms。
  原生 X、input_manager 和 btmanagerd 在测试后保持运行；Android 锁、电源恢复
  文件和 Android 进程均已释放。没有进行物理触控、蓝牙按键或 USB 插拔测试。
- 更新后第一次冷启动包含缓存重建，软件就绪为 192498 ms；最初测试的 180 秒
  等待超时，随后设备实际进入 active。不能将该轮标记为 180 秒内启动成功。
- 完整退出软件就绪为 13847 ms。Android 内层退出码为 0，外层为 1。
  后续发现清理钩子注入规则仅匹配两个空格，实际运行脚本为一个空格。
  已修复缩进匹配并增加缺失锚点检查。回归命令：
  `python tests/test_cleanup_hook.py`，覆盖实际脚本、两空格、Tab 和缺失锚点。
- 最终本地安装包 `c100ff4903e88a76716ffeba2838329de20c34428acd267ada8bf2c1cd44c541`
  已通过 41 步构建验证，但最后的清理钩子修复尚未部署：设备完整退出后 SSH
  再次超时。不能把本地测试通过当作外层退出码问题已经实机修复。

设备最后确认处于 Kindle 首页，Android 已完整退出。蓝牙退出后失效的根因和
最后清理补丁的实机效果仍需后续验收；未重启或重置原生蓝牙服务。


## 后续蓝牙翻页修复验收

已接入原生 kindle-input-pt 虚拟键盘并添加 PAGE_UP/PAGE_DOWN 布局。
该设备宣告全部按键，原先被 Android 7 误判为外接触笔；现在只收窄容器客户端
的能力位图，原生内核设备和蓝牙配对不变。Android 输入服务已确认键盘分类与
两枚翻页键支持。蓝牙按键复用触屏的完成手势记录，方向分别为 2/3，动画开关
与步数由原有显示模块统一决定。最终包 SHA256：
`3791cd0978a8f3bda54e4900c8c3976a15b036d763c00ed4eb97dc27a350e08d`。
用户已确认微信读书中“翻页和动画都正常”。此结论取代前文未接通的阶段性状态，
不代表退出后的原生蓝牙翻页、长按和断线重连均已验收。
